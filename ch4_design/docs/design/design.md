# 실험 설계 고정본

학위논문 평가 장을 다시 짓기 위한 설계다. **이 문서를 커밋하고 태그를 단 뒤에 생성과 수집을 시작한다.**
결과를 본 뒤 지표, 조건, 임계를 바꾸면 이 문서에 날짜와 이유를 남긴다.

심사 지적은 둘이다. 품질 특성(정확성)이 평가의 중심이어야 하고, 비교는 기준 하나를 두고 해야 한다.
그래서 평가를 **정확성**과 **행동 다양성** 둘로만 나누고 조건 수를 줄인다.

## 연구 질문

| | 질문 | 실험 |
|---|---|---|
| RQ1 | 행동 분류 기반 생성은 제로샷보다 정확한 트리를 만드는가, 오류 수정은 같은 트리의 정확성을 얼마나 올리는가 | 실험 1, 실험 2 정확성 |
| RQ2 | 같은 파라미터 범위 안에서, 트리를 얹은 배경차가 고정 추첨보다 행동 다양성이 높은가, 그 대가는 무엇인가 | 실험 2 다양성 |

## 정확성 지표

두 실험이 같은 표 형식을 쓴다. 지표 넷은 발표 덱의 품질 요소 표를 따른다.

| 지표 | 정의 | 실험 1 | 실험 2 |
|---|---|---|---|
| 구조 유효성 $V$ | 형식 검증(XML 문법, BT 스키마, 트리 구조, 실행 런타임 로딩과 1틱)을 통과한 트리 비율 | O | O |
| 의미 오류 수 | 카탈로그 밖 노드 ID, 정의역 밖 인자, 선언 후 미사용 파라미터, 미선언 파라미터 참조. 트리당 유형별 개수 | 해당 없음 | O |
| 도달 불가 규칙 수 | 폴백 아래 앞 자식의 조건이 뒤 자식의 조건에 함의되어 뒤 자식이 실행될 수 없는 경우. 트리당 개수 | O | O |
| 행동 포괄률 $C$ | 기대 행동 중 트리에 담긴 비율. 키워드 일치 판정 | O | 해당 없음 |

- 형식 검증 4단계의 런타임은 실험마다 실제로 트리를 돌리는 쪽이다. 실험 1은 BT.CPP v4 로더(리프는
  성공 스텁), 실험 2는 CARLA 수집에 쓰는 py_trees 실행기([`scripts/bt_runtime.py`](../scripts/bt_runtime.py))
- 실험 1은 노드 이름이 자유라 카탈로그가 없어 의미 오류 수가 정의되지 않는다
- 실험 2는 CARLA 배경차의 기대 행동 목록이 없어 포괄률이 정의되지 않는다
- 도달 불가 규칙은 경고로 집계만 하고 수정 피드백에 넣지 않는다. 수정은 구조 오류만 고치고 규칙 순서를
  포함한 행동 내용은 안 바꾼다

### 짝지은 기록

같은 트리를 수정 전 초안과 수정 후 최종본으로 짝지어 기록한다. 트리마다 남기는 것:

- 초안 XML, 매 수정 회차의 후보 XML, 최종 XML
- 회차마다 전체 오류 목록과 정규화한 오류 유형
- 오류 유형별로 처음 사라진 회차
- 상한 도달 여부와 최종 유효 여부를 따로

보고는 오류 유형별 누적 해소율(회차 $k$까지 사라진 비율)로 한다.

## 실험 1. 생성 트리의 정확성

기대 행동 비노출, 3개 도메인. **KCC2026 로그를 다시 분석한다. 새 생성은 안 한다.** GPT-4
(`gpt-4-0613`)는 2026-10-23에 서비스가 끝나 다시 생성할 수 없다.

| 항목 | 값 |
|---|---|
| 대상 | 엘리베이터, 드론, 스마트 팩토리의 환경 에이전트 11개, 기대 행동 73개 |
| 입력 | 에이전트 이름과 설명만. 기대 행동은 평가에만 쓴다 |
| 비교 | 제로샷 대 제안(행동 분류 기반 3단계), 각각 수정 전과 후 |
| 모델 | GPT-4(`gpt-4-0613`), Llama-3.3-70B-Instruct-Turbo |
| 반복 | 조건마다 에이전트 11개 x 10회 = 트리 110개 |
| 수정 상한 | 3회 |
| 부록 | 퓨샷, 제안+퓨샷 |

로그에 트리마다 초안과 최종 XML, 회차별 오류 문자열이 있어 짝지은 기록이 복원된다. 중간 회차 XML은
없어서 도달 불가 규칙 수는 수정 전과 후 두 점만 낸다.

통계:

- 분석 단위는 에이전트(n = 11). 에이전트마다 10회 평균을 낸 뒤 비교한다
- 제로샷 대 제안, 수정 전 대 후: 에이전트 단위 Wilcoxon 부호순위(양측), 모델별
- 평균차의 95% 신뢰구간: 에이전트 재표집 부트스트랩 10,000회
- 다중비교: 모델 하나 안의 검정 묶음에 Holm 보정

## 실험 2. CARLA

시뮬레이터 함수 제공.

### 정확성

실험 1과 같은 지표, 같은 짝지은 기록이다.

| 항목 | 값 |
|---|---|
| 대상 | CARLA 0.9.10 배경 차량 |
| 입력 | 에이전트 설명, 노드 카탈로그(행동 8, 조건 20), 파라미터 범위 |
| 비교 | 제로샷 대 제안(4단계: 분해, 유도, 배치, 합성), 각각 수정 전과 후 |
| 모델 | Llama-3.3-70B-Instruct. OpenRouter 경유, 프로바이더 CoreWeave fp16 고정, 대체 경로 금지 |
| 반복 | 전략마다 독립 생성 실행 2회 x 트리 10개 = 20개 (세트 `zs_r1`, `zs_r2`, `prop_r1`, `prop_r2`) |
| 온도, 출력 상한 | 0.7, 4,096 토큰 |
| 수정 상한 | 6회 |

행동 노드 범위를 추첨 범위와 같게 바꾸므로 새로 생성한다. 앞 레포의 학위논문 트리 20개(`p0`, `zs`)를
새 검증기로 보면 **20개 전부** 추첨 범위 밖 값을 쓴다(합 114건). 트리 수가 적어 검정 없이 기술
통계와 트리 단위 전이 표로 보고한다.

배치 단계: 실험 1의 KCC판 3단계에는 규칙 순서를 정하는 단계가 없었고, 실험 1의 도달 불가 규칙은
대부분 조건 없는 서브트리가 앞에 놓인 경우였다. 실험 2의 4단계는 배치 단계를 더했다. **배치 단계의
효과는 주장하지 않는다.** 그 단계만 뺀 비교를 안 하고, 실험 2는 카탈로그(조건 노드 강제)도 함께
달라서 두 요인이 갈리지 않는다. 서술로만 적는다.

모델 경로: 앞 실험은 Together의 `Llama-3.3-70B-Instruct-Turbo`(fp8)였는데 2026-10에 서버리스 제공이
끝났다. 같은 가중치를 OpenRouter로 부르고, 프로바이더를 원 정밀도(fp16)인 곳 하나로 못 박았다.
호출마다 응답한 프로바이더를 기록한다.

### 행동 다양성 조건

| 조건 | 차량마다 다른가 | 에피소드 중 바뀌는가 | 설정 |
|---|---|---|---|
| **기준** | 같음 | 고정 | 모든 차량이 같은 기준값. 다양성 = 1 |
| **추첨** | 다름 | 고정 | 차량마다 범위 안에서 균등 추출, 에피소드 내내 유지 |
| **트리** | 다름 | 바뀜 | 차량마다 트리 배정. 발화한 규칙이 값을 덮어씀. 발화 없으면 기준값 |

- 트리 조건은 제안 전략으로 생성해(`prop_r1`, `prop_r2`) 수정이 끝난 트리 **전부**를 쓴다. 고르지 않는다. 상한까지 수정해도
  실행 불가로 남은 트리만 빠지고 그 수를 보고한다
- 결합 조건과 최상위 조건은 없다

### 범위 일치

트리가 쓰는 파라미터 범위를 추첨 범위와 똑같이 맞춘다.

| 파라미터 | 기준값 | 범위 (추첨 = 트리) |
|---|---|---|
| `speed_diff` (%) | 0 | -30 ~ 30 |
| `gap_m` (m) | 2.5 | 0.5 ~ 4.5 |
| `keep_right` (%) | 50 | 0 ~ 100 |
| `ign_lights` (%) | 0 | 0 ~ 10 |
| `ign_signs` (%) | 0 | 0 ~ 10 |
| `ign_vehicles` (%) | 0 | 0 ~ 5 |
| `ign_walkers` (%) | 0 | 0 ~ 5 |
| 차로 변경 허용 | true | {true, false}. 추첨은 true 확률 0.8 |

카탈로그가 LLM에 보여주는 범위, 검증기의 정의역 판정, 실행기의 클램프를 모두 이 표 하나에서 만든다.

### 주 지표

행동 다양성 하나. 도로 유형(교차로, 도심, 고속)마다 따로 잰다.

1. 궤적을 도로 유형으로 나누고, 도심 40 m, 고속 80 m, 교차로는 통과 구간 전체를 단위 하나로 자른다
2. 단위마다 특징 다섯: 속도 평균과 표준편차, 가속도 평균과 표준편차, 100 m당 가속도 부호 변화 횟수
3. 특징을 도로 유형별 실측 표준편차 $\sigma_s$([`config/scale.yaml`](../config/scale.yaml))로 나눠 무차원화
4. 폭 1인 격자에 넣고 칸 빈도로 실효 칸 수를 센다. 격자 원점 20개 평균

$$D = \exp\Big(-\sum_c p_c \ln p_c\Big)$$

5. 실행마다 같은 단위 수를 비복원 추출해 센다(그 도로 유형에서 세 조건 전 실행의 최소 단위 수)
6. 맵마다 조건의 시드 평균 $D$를 기준 조건의 시드 평균 $D$로 나눈 배수를 보고

배수는 세 조건을 한 번에 채점한 판에서만 읽는다.

## 실행 순서

자세한 단계는 [`docs/plan.md`](plan.md)에 있다.

1. 이 문서를 고정한다
2. 트리를 생성하고 수정 전후 정확성을 기록한다(실험 1 재분석, 실험 2 생성)
3. 수정이 끝난 제안 트리 전부로 CARLA에서 기준, 추첨, 트리를 수집한다
4. 다양성과 부작용을 한 판으로 채점한다

평가 장 슬라이드는 셋이다.

1. 오류 수정 전후 정확성 표(두 실험)
2. 기준 대비 행동 다양성(기준, 추첨, 트리), 도로 유형별
3. 부작용 비교

## 보조 실험. 상황별 개성

2026-11-09 추가. 사후 실험이다(동기가 본 결과). 다만 아래 규칙은 **이 지표를 한 번도 계산하기 전에**
고정했고, 결과를 본 뒤 바꾸면 [변경 기록](#변경-기록)에 남긴다. 구현은 [`diag/context.py`](../diag/context.py).

### 질문

주 지표와 자 넷은 단위를 섞어 분포 폭만 본다. 차량마다 **상황에 따라 반응하는 방식**이 다른지는 못 본다.
추첨은 차량마다 노브 하나를 모든 상황에 같이 쓰고, 트리는 차량마다 다른 트리가 상황별 값을 따로 쓴다.
트리가 의도대로 돌면 차량 x 상황 상호작용이 추첨보다 커야 한다. 새 수집 없이 기존 아홉 조건 수집물로 잰다.

### 상황과 단위

- 단위는 주 지표와 같다(도심 40 m, 고속 80 m, 교차로 통과 전체). 단위에 상황 라벨만 붙인다
- 앞차: 트리 실행기 지각 그대로. 자차 진행방향 원뿔 종 0.5~100 m, 횡 2 m 안에 다른 차가 있으면 앞차 있음
  (`bt_nodes.SENSE`). 차로 번호와 횡위치는 안 씀
- 단위의 앞차 비율 0.8 이상이면 **추종**, 0.2 이하면 **자유**, 사이는 버림
- 1차 분석은 도심(`urb_block`)의 추종 대 자유. 고속은 맵 3개라 기술만
- 2차 분석은 교차로 대 도심(앞차 무관 전체 단위)

### 추정량

차량 $v$의 단위를 그 차 단위 중간 시각의 중앙값으로 앞반 A, 뒷반 B로 나눈다. 반마다 상황별 단위가 2개 이상인
차만 쓴다. 특징 $f$(KIN 다섯, `scale.yaml`로 나눔)마다 반 $h$에서

$$\Delta^h_{vf} = \bar x^h_{vf,\text{추종}} - \bar x^h_{vf,\text{자유}}, \qquad L^h_{vf} = \tfrac12\big(\bar x^h_{vf,\text{추종}} + \bar x^h_{vf,\text{자유}}\big)$$

실행 안에서 차량 평균을 빼고(실행 수준 차이 제거) 맵의 8개 실행을 모아

$$S = \sum_f \widehat{\mathrm{cov}}_v\big(\Delta^A_{vf}, \Delta^B_{vf}\big), \qquad I = \sum_f \widehat{\mathrm{cov}}_v\big(L^A_{vf}, L^B_{vf}\big)$$

두 반의 측정 잡음은 독립이라 공분산에서 빠지고, 차량마다 반복되는 몫만 남는다(random slope와 random
intercept 분산의 모형 없는 추정). 적격 차량이 20대 미만인 맵은 그 조건에서 뺀다.

- **주 지표: $S$, 상황 의존 분산.** 클수록 차량마다 상황 반응 방식이 다르다
- 보조: $I$(차량 개성 분산), 몫 $S/(S+I)$, 특징별 $S$
- 몫을 주 지표로 안 쓰는 이유: 트리 단독은 차량 사이 수준 폭이 좁아($I$가 작아) 몫이 저절로 커진다

### 비교와 판정

- 1차 가족(도심, $S$): `offkrw05-knobw05`, `offkr-knob`, `offkrw2-knobw2`, `tree-knob`. 맵 8개 대응
  Wilcoxon 부호순위, 넷에 Holm
- **같은 폭에서 트리가 상황별 개성을 더한다**고 쓰는 조건: 같은 폭 짝 셋이 모두 양수이고 둘 이상이 Holm
  p < 0.05. 판단으로 정한 규칙
- **트리 단독이 추첨보다 상황 의존적이다**: `tree-knob`이 양수이고 Holm p < 0.05
- plain은 바닥(차종과 경로만으로 생기는 몫). `offset-knob`, `knob-plain`, 2차 분석, 보조 지표는 기술
- 조작 확인: 트리를 쓴 조건에서 차량별 $\sum_f \Delta^A_{vf}\Delta^B_{vf}$와 plan 로그의 gap_m,
  speed_diff 실행 중 sd(트리가 그 차 값을 얼마나 바꿨나)의 Spearman 상관을 맵마다 내고 맵 평균. 양의 방향을
  예상. 로그 sd가 상황 구분 없이 섞인 값이라 약한 확인
- 민감도: 상황 임계 0.7/0.3, 0.9/0.1, 반당 최소 단위 1, 3. 결론 방향이 유지되는지만 본다

### 한계

  비교에는 상쇄된다고 가정

### 추정량

실행(맵, 시드, 조건)마다 차량 간 분산을 낸다. 클수록 차량마다 그 행동 성향이 다르다.

- **L1:** 다차로 노출 0.05 km 이상인 차. 차량별 횟수 $c_v$, 노출 $e_v$, $\hat r=\sum c_v/\sum e_v$에서
  $$\hat\sigma^2_{L1}=\frac{\sum_v (c_v-\hat r e_v)^2-\sum_v \hat r e_v}{\sum_v e_v^2}$$
  포아송 잡음을 뺀 적률 추정(포아송-감마)
- **L2:** 두 반 모두 다차로 50 프레임(5 s) 이상인 차. 반별 맨 오른쪽 비율 $f^A_v, f^B_v$의 교차 공분산
  $\hat\sigma^2_{L2}=\widehat{\mathrm{cov}}_v(f^A_v,f^B_v)$. 반 잡음은 독립이라 빠짐(상황별 개성과 같은 생각)
- 실행에 적격 차량이 20대 미만이면 그 실행 값은 비움
- **C1:** 맵마다 8 시드를 모아 베타-이항 적률 추정, 실행별 평균 비율로 중심화. 맵 단위만 남아 기술
- 평균 성향($\hat r$, 평균 오른쪽 비율, C1, C2 비율)은 기술

## 보조 실험 3. 차로 변경 빈도의 실측 비교

2026-11-11 추가. 사후 실험이다(동기는 보조 실험 2에서 트리가 차로 변경 평균을 크게 옮긴 것). 아래 규칙은
**실측 쪽 차로 변경 값을 한 번도 계산하기 전에** 고정했다. 고정 전에 본 실측 정보는 NGSIM Peachtree,
Lankershim의 열 구조와 코드 분포(차로, 교차로, 방향, 차종)뿐이다. 문헌 근거는 아래 각 항목에 붙였다.
구현은 [`diag/lanechange.py`](../diag/lanechange.py).

### 질문

트리 결합이 CARLA 배경 차량의 차로 변경 빈도를 **실측 쪽으로** 옮기는가. 평균이 움직였다는 것만으로는 현실성을
말할 수 없어서(보조 실험 2), 같은 정의로 센 실측 빈도와의 거리를 조건마다 비교한다.

### 범위

- **주 비교, 도심:** CARLA 다차로 구간 중 `urb_block` 층(보조 실험 2의 다차로 정의 그대로) 대
  NGSIM Peachtree, Lankershim(도심 간선)
- **기술, 고속:** CARLA 다차로 `hw_link` 층(Town04, 06) 대 NGSIM I-80, US-101. highD는 이번엔 안 씀
  (25 Hz, 파일 수가 많아 정의 맞추는 비용 대비 고속이 기술용이라)
- **뺀 것:** 막힘 대응. CARLA는 신호 영향 프레임을 막힘에서 뺐는데 NGSIM에는 신호 상태가 없어 정의를 못 맞춤.
  차량별 이질성. NGSIM은 차 한 대를 500~640 m만 봐서 차량별 성향을 못 냄

### 정의 (양쪽 같게)

- **차로 변경:** 같은 구간(CARLA 도로 한쪽 방향, NGSIM 구역과 방향) 안에서 τ 이상 유지된 차로끼리 바뀐 것.
  그다음 다른 변경과 5 s 안에 붙은 변경은 둘 다 버림(Thiemann, Treiber, Kesting 2008, TRR 2088. NGSIM 추적이
  차선 경계를 넘었다 돌아오는 오류를 이렇게 거름). 주 τ = 1 s
- **실측 범위:** 도심은 교차로 밖(`int_id` 0), 주도로(`direction` 2, 4), 직진 차로 1~4, 승용과 트럭(`v_class`
  2, 3). 회전 전용 차로(11, 12, 31, 101 등)는 CARLA 쪽이 차로 구성이 바뀌는 구간을 뺀 것과 맞추려고 뺌.
  고속은 왼쪽 차로 1~4(Thiemann 2008과 같이 램프와 보조 차로 제외)
- **노출:** 그 범위 안 주행 거리(차량 km). 빈도 = 차로 변경 수 / 차량 km
- **국소 밀도:** 그 프레임에 같은 구간, 같은 방향, 범위 안 차로에서 앞뒤 50 m 안의 다른 차 수 /
  (0.1 km x 그 구간 차로 수). veh/km/lane. 차로 변경과 노출을 밀도 칸에 나눠 담음(Knoop et al. 2010,
  Kruber et al. 2019: 차로 변경 빈도가 밀도에 크게 걸림). 구간 끝에서 창이 잘리는 건 양쪽 모두 있음
- **밀도 칸:** 주 A = [0, 10), [10, 20), [20, 40), 40 이상. 민감도 B = [0, 15), [15, 30), 30 이상. 판단값

### 추정량과 판정

- **밀도 표준화 빈도:** 실측 현장 $s$의 칸별 노출 비중 $w_{sb}$로 CARLA 조건의 칸별 빈도를 가중 평균
  $r_{\text{std}}=\sum_b w_{sb}\, r_b$. 양쪽 노출이 모두 1 km 이상인 칸만 쓰고 $w$를 다시 정규화.
  실측 빈도도 같은 칸으로 $r_s=\sum_b w_{sb} r_{sb}$
- **거리:** $d = |\log(r_{\text{std}}/r_s)|$. 대칭, 단위 없음
- **대비:** $\Delta = d(a) - d(b)$. 주 가족: `offkrw05-knobw05`, `offkr-knob`, `offkrw2-knobw2`, `tree-knob`.
  기술: `knob-plain`, `offset-knob`, `treero-tree`
- **CI:** 부트스트랩 2,000회(시드 0). CARLA는 (맵, 시드) 묶음을 두 조건에 같게 다시 뽑고, 실측은 차량을 다시
  뽑아 두 조건에 같은 실측 표본을 씀. 백분위 95%
- **실측 쪽으로 옮김:** 세 조건을 모두 만족할 때만 쓴다.
  1. 두 현장 각각에서 $\Delta$의 CI 상한이 0 미만
  2. 두 현장이 같은 방향
  3. 조건 간 이동 $|\log(r_{\text{std}}(a)/r_{\text{std}}(b))|$가 현장 사이 거리 $|\log(r_{PT}/r_{LK})|$보다 큼.
     실측끼리 이만큼 다르면 그 안의 이동은 판정 안 함
  
  선례 없는 판단 규칙(문헌에서 같은 판정을 찾지 못함)
- **반대 방향:** 1, 2를 부호 반대로 만족하면 **실측에서 멀어짐**으로 씀
- 민감도: τ 0.5 s, 2 s, 밀도 칸 B. 방향 유지만 봄

### 한계

- 도로 형태와 수요가 다름. 밀도로 조건을 걸어도 차로 수, 구간 길이, 회전 수요 차이는 남음
- NGSIM 도심 차로 번호 품질을 따로 검증한 문헌을 못 찾음(Punzo et al. 2011, Coifman and Li 2017은 NGSIM 궤적
  오차 일반). 되돌림 필터가 일부만 거름
- 부트스트랩은 두 분포가 가까울 때 덜 덮을 수 있음(Wasserstein 관련 지적). 판정에 현장 사이 거리 조건을 둔 이유
- 현장 둘로 실측 변동을 대표하기엔 적음

2026-11-18 추가. 사후 실험, 탐색. 새 수집 없음. 아래 규칙은 검사 결과를 **한 번도 계산하기 전에** 고정했다.
고정 전에 본 것은 트리 json의 키 구조, `prop_r2/tree_06` 한 트리의 enumeration 원문, 제안 트리 20개 enumeration

### 질문

실험 2 정확성은 정적 검사(실행 가능, 의미 오류)만 본다. 트리가 합성 전에 스스로 적은 규칙(`intermediate.enumeration`의
"When C, A")을 **가능한 모든 지각 입력에서** 지키는지, 기존 도달 불가 판정(`bt_nodes.unreachable`의 함의 규칙)이
맞는지는 안 봤다.

### 검사가 정확한 근거

실행기([`bt_runtime.py`](../scripts/bt_runtime.py))에서 합성 노드는 `memory=False`라 매 틱 루트부터 재평가하고,
리프는 즉시 반환해 RUNNING이 없고, 틱 시작마다 명령을 기준값으로 되돌린다. 그래서 트리는 틱마다 지각값 $p$와
차량 파라미터 $\theta$에서 명령 벡터를 내는 **상태 없는 함수** $f(p,\theta)$다. 틱 사이 기억은 환경(`lane_time_s` 등)에만
있다. 따라서 트리 쪽 성질 $\varphi(p, f(p,\theta))$가 정의역 $\mathcal D$ 전체에서 성립하면 어떤 환경, 어떤 실행에서도
매 틱 성립한다(시간 논리 G φ와 같음). 환경과 TM을 모형화할 필요가 없다. 반대로 위반 입력은 $\mathcal D$가 넓으면
실제 주행에서 안 나오는 입력일 수 있다. 이 비대칭 때문에 정의역을 두 단계로 둔다.

### 정의역

$p$의 15개 항목을 `EVAL`과 같은 의미로 SMT 변수로 둔다(z3). $\theta$는 트리 `<Params>` 선언 구간.

정의역은 카탈로그 범위가 아니라 **지각 함수(`bt_runtime.Perception`)의 치역**에서 잡는다. 카탈로그 범위로 잡으면 실제로
안 나오는 값(예: 교차로 거리 15 m)에서 가짜 위반이 나온다.

- **느슨(주):** 속도 $[0, \text{MAX\_SPEED}]$, `stopped` ⇔ 속도 < 1.8 km/h, 선행차 없으면 간격 999와 `dv` 0, 있으면 간격
  $[-10, 100]$(중심 거리에서 반 길이 둘을 빼서 음수 가능)과 `dv` $[-\text{MAX\_DV}, \text{MAX\_DV}]$, 교차로 거리
  {10, 20, ..., 60, 999}(10 m 간격 탐색), 신호 {없음, Red, Yellow, Green}, 제한속도 $[0, 90]$, 맨 왼쪽과 맨 오른쪽은
  각각 왼쪽, 오른쪽 이웃 차로 수가 0일 때, 차로 수 = 왼쪽 + 오른쪽 + 1(각 0~4), 차로 유지 시간 $\ge 0$, 곡률
  $[0, \pi/10]$
- **조임(민감도):** 선행차 속도 $= v/3.6 - dv \ge 0$, `lead_stopped` ⇔ 선행차 속도 < 0.5 m/s, 제한속도는 여덟 맵 xodr에
  나오는 값 집합(주 지표 `measure.road_map`의 `lim`). 판단값

### 검사기 검증

SMT 모형이 실행기와 같은 함수인지 먼저 확인한다. 트리마다 느슨 정의역에서 균등 추출한 $(p,\theta)$ 10,000개에서 모형
명령과 `bt_runtime.tick` 명령이 전부 같아야 한다. 하나라도 다르면 결과를 내지 않고 모형을 고친다.
비교 기준 실행기는 **수집과 같은 py3.7 환경(py_trees 2.1.6)**에서 돌린다. py3.11에는 py_trees 2.4.0이 깔려 있고 제안 트리
20개 중 17개가 `Parallel`을 써서, 판이 다르면 의미가 갈릴 수 있음. 두 판 출력이 같은지도 같이 보고. 모형은 `Parallel`이
모든 자식을 틱하고, `Sequence`가 중간에 실패해도 앞서 발화한 행동의 쓰기가 남는 부작용을 그대로 따라야 함. 반례 입력은 SMT 결과를
실행기에 넣어 재현되는지 하나씩 확인

### 규칙 번역

- 줄 형식 "When C, A"와 "If C then A" 둘을 정규식으로 읽음. C는 `and`로 이은 카탈로그 조건, A는 카탈로그 행동 하나
- 값이 `{이름}`이면 트리 `<Params>`의 같은 이름 $\theta$, 아니면 리터럴
- 카탈로그 밖 ID, `or`, 부정, 행동 둘 이상, 이름이 트리에 없는 파라미터는 **번역 불가**로 세고 뺀다. 번역 불가
  비율을 같이 보고. LLM으로 번역하지 않음

### 성질과 분류

규칙 $r=(C_r, k_r, a_r)$마다 $f_k$를 노브 $k$의 명령이라 할 때:

- **공허:** $C_r$를 만족하는 $(p,\theta)$가 없음
- **불이행:** $C_r$는 만족 가능하지만 $C_r \wedge f_{k_r}=a_r$는 불가능
- **일부 이행:** 둘 다 가능
- **항상 이행:** $C_r \wedge f_{k_r} \ne a_r$가 불가능

일부와 불이행은 원인을 나눈다. 같은 enumeration 안에 같은 노브에 다른 값을 쓰는 규칙 $r'$이 있고 $C_r \wedge C_{r'}$가
만족 가능하면 **계획 충돌**이다. $C_r \wedge \bigwedge_{r'} \neg C_{r'} \wedge f_{k_r} \ne a_r$(충돌 규칙이 하나도 안 걸린
입력에서의 위반)가 가능하면 **합성 위반**이다. 값 비교 허용오차 $10^{-6}$.

- **기준값 규칙:** $a_r$가 그 노브의 기준값(`baseline_want`)과 같거나 $\theta$ 구간이 기준값을 품으면, 트리가 아무것도 안
  써도 이행으로 잡힌다. 이런 규칙은 따로 세고 이행 비율은 이를 뺀 것과 넣은 것 둘 다 보고
- **값 일치만 봄:** 다른 규칙이 우연히 같은 값을 써도 이행으로 잡힘. 발화 노드까지 맞추지 않음(규칙과 노드 대응이 없어서)
- 일부 이행은 $p$에 따른 것과 $\theta$(차량 추첨)에 따른 것이 섞임. 둘을 가르려고 $\forall\theta$ 항상 이행 여부를 같이 냄

**도달 검사:** 행동 노드마다 그 노드가 발화하는 입력이 있는지(발화 가능), 그 노드의 쓰기가 틱 끝 명령으로 남는
입력이 있는지(유효). `unreachable` 경고와 교차표.

### 추정량

실행(맵, 시드, 조건), 상황마다 **칸 조건부** Hill 수 $D=\exp\big(\sum_c w_c H_c\big)$, $H_c=-\sum_k p_{k|c}\ln p_{k|c}$.
$w_c$는 그 맵에서 비교하는 조건들을 합친 칸 비중으로 고정(조건마다 칸 구성이 달라도 같은 가중). S2, S3는 칸이 하나라
보통 Hill 수 q1 $D=\exp(-\sum_k p_k \ln p_k)$. 표본 수를 맞추려고 그 맵, 상황에서
비교하는 조건들의 실행 최소 사건 수만큼 비복원 추출해 20회 평균(주 지표 5단계와 같은 생각). 최소 사건 수가 20 미만인
(맵, 상황)은 뺌. 칸별 사건이 5 미만인 칸은 그 실행에서 뺌. 맵마다 시드 평균.

해석용으로 유형 수(q0)와 최빈 유형 비율(Berger-Parker)을 같이 낸다. 주 판정은 q1만.

바꿀 뿐 퍼짐을 직접 넓히지 않는다. 오르지 않으면 의미 오류와 다양성 부족은 별개 문제라는 증거로 읽는다.

### 카탈로그 v2

v1(실험 2 그대로)에서 아래만 바꾼다. 실행기, 검증기 정의역, KNOBS, 프롬프트의 나머지는 그대로. 기존 트리와 수집물에는 영향 없음.

- **SetSpeedDiff:** 설명을 "제한속도보다 몇 % 느리게 가는가. 양수는 감속(10이면 제한의 90%), 음수는 초과(−10이면 110%). 감속하려면
  양수"로 바꿈. 의도와 값이 반대인 규칙의 원인으로 본 곳
- **JunctionAhead:** 설명에 "교차로 거리는 10 m 단위(10, 20, ..., 60)로만 보이고 10 m 이하 임계는 참이 안 된다"를 넣고, 임계
  범위를 0~60에서 11~60으로 바꿈. 검증기가 이 범위로 거르므로 10 이하는 수정 루프에서 오류로 돌아감
- **TimeInLaneAbove:** 설명에 "도로가 바뀌면 0으로 돌아간다(도로 중앙값 약 35 m)"를 넣음
- `IsLeftmostLane`, `LaneCountAbove`는 반대 방향 차로를 세는지 확인 전이라 안 바꿈(두 조건 모두 같은 실행기라 대비에는 공통)

### 트리 세트와 조건

- **fixc(대조):** 카탈로그 v1로 다시 생성. 실험 2 제안 방식과 같은 설정(Llama-3.3-70B, 프로바이더 고정, 온도 0.7, 4단계, 수정 6회),
  세트 둘 x 10 = 20개(`fixc_r1`, `fixc_r2`)
- **fixf(수정):** 카탈로그 v2로 같은 설정, `fixf_r1`, `fixf_r2`
- 트리를 고르지 않음. 수정 후 실행 불가만 빠짐
- **조건 `treec`, `treef`:** 트리 단독(`tree`와 같은 실행 방식)에 각 세트. 8 맵 x 시드 0~7 = 각 64회, `data/outputs/arms_fix`
- 채점은 `plain`, `knob`, `tree`(기존 시드 0~7 수집물)와 한 판(`results/fix`). 배수는 이 판 안에서만 읽음

### 조작 확인(수집 전, 생성 직후)

새 세트에 [보조 실험 8](#보조-실험-8-규칙의-의도와-타당성) 자동 판정과 [보조 실험 6](#보조-실험-6-트리-수준-전수-검사) 검사를
그대로 돌림.

- 주: 판정한 speed_diff 규칙 중 불일치 비율, fixf 대 fixc. 두 비율의 차이와 Newcombe 95% 구간
- 기술: `JunctionAhead` 공허 규칙 수, 실행 가능 비율, 수정 회차, 번역 비율, 규칙 분류 분포
- 조작이 안 됐어도(fixf 불일치가 안 줄어도) 수집은 함. 그 경우 다양성 결과를 **수정의 효과**로 읽지 않음

### 다양성 대비와 판정

- **주:** `treef - treec`, 교차로와 도심. 맵 단위 차이 평균과 95% t CI, Wilcoxon
- **판정:** 교차로 CI 하한 > 0이면 **수정으로 다양성 오름**. 상한 < 0이면 **내림**, 0을 품으면 **판정 안 함**
- **기술:** `treef - knob`, `treec - knob`, `treec - tree`(같은 카탈로그로 다시 뽑은 세트 사이 차이, 트리 세트 표본 잡음의 크기),
  precision/recall, 차로 변경 빈도, 충돌
- 강건성: 격자 폭 0.5와 2, 차수 q0과 q2. 방향 유지만

### 하지 않는 것

- 결합 조건(`offkr`)에 새 트리 얹기. 트리 단독 회복이 질문이라 뺌. 단독이 오르면 다음에
- 실행기 수정. 실행기를 바꾸면 기존 조건과 비교가 깨짐

### 한계

- 세트 둘 x 10은 트리 세트 표본 잡음이 클 수 있음. `treec - tree`가 그 크기를 보여 줌
- 카탈로그 문구 하나에 대한 결과라 다른 문구, 다른 모델로 일반화 안 함
- 생성 시점이 실험 2와 달라 프로바이더 쪽 변화가 섞일 수 있음. fixc가 이걸 같이 받음
